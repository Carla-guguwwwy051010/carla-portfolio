# Personal OS｜迭代计划

## 迭代目标

Personal OS 下一阶段不以继续增加固定模块为重点，而是沿两条主线演进：

1. 从固定系统升级为可 DIY、可按身份定制的个人系统。
2. 从手动填写升级为由真实 AI 辅助的自然语言记录，同时保证用户对数据的控制权。

以下为产品规划，不代表相关能力已经实现。

## Phase 0｜当前概念验证版

**已有基础**

- 单文件 Web App。
- LocalStorage 本地存储。
- Dashboard 与多个固定场景模块。
- 手动记录与查看流程。
- AI 仅为模拟或探索。

**阶段价值**

验证统一入口、模块划分和本地优先形态是否能够支撑 Personal OS 的核心概念。

## Phase 1｜模块 DIY 与首页定制

**目标：** 让用户只保留与自己相关的部分，降低固定系统带来的信息负担。

**计划能力**

- 模块显示与隐藏。
- 模块拖拽排序。
- Dashboard 卡片选择与排序。
- 保存个人配置。
- 恢复默认布局。
- 配置变更前预览，避免误操作。

**验证重点**

- 用户能否理解“模块”和“首页卡片”的区别。
- 定制过程是否比直接使用默认结构更复杂。
- 用户是否能在完成设置后快速找到高频入口。

## Phase 2｜基于身份的个性化

**目标：** 降低从零搭建 Personal OS 的门槛，让系统结构贴合用户当前身份。

**计划能力**

- 支持选择多个身份，如学生、产品经理、家教、创作者。
- 根据身份推荐模块组合与 Dashboard 布局。
- 支持“当前主身份”或阶段重点影响首页优先级。
- 用户可随时修改推荐结果。
- 身份变化时保留原有数据，不强制删除模块内容。

**设计原则**

身份是初始化与推荐依据，不是固定标签。系统提供骨架，用户拥有最终编辑权。

## Phase 3｜真实 AI 助手与对话式记录

**目标：** 把自然表达转换为结构化草稿，减少寻找模块和逐字段填写的成本。

**计划能力**

- 接入真实大模型。
- 支持聊天式文本输入。
- 在条件允许时接入语音转文字。
- 识别意图、所属身份、目标模块、时间和关键字段。
- 同一段输入可拆分为多条候选记录。
- 低置信度时追问或展示多个候选位置。
- 用户修改并确认后再写入。

**示例**

用户输入：“今天把 Personal OS 的模块结构整理完了，下一步做首页定制。”

AI 可建议写入 PM Workspace 或 Creation，并生成“已完成事项”和“下一步”草稿；最终模块和字段由用户确认。

## Phase 4｜可信 AI 操作层

**目标：** 让 AI 的便利建立在可控、可恢复和可审计的基础上。

**必须具备**

- **可预览：** 执行前展示即将新增或修改的内容。
- **可确认：** 未确认的结果只保存为草稿。
- **可撤销：** 对已执行写入提供明确撤销入口。
- **可追溯：** 记录原始输入、AI 建议、用户修改、最终结果和操作时间。
- **权限分级：** 新增、修改、删除和批量操作采用不同确认强度。
- **失败保护：** 模型或网络异常时不产生不完整的静默写入。

## 迭代优先级

| 优先级 | 方向 | 原因 |
|---|---|---|
| P0 | 模块 DIY、配置保存 | 先解决固定结构与个体差异 |
| P0 | AI 写入的确认与撤销框架 | 应在真实模型接入前建立安全边界 |
| P1 | 身份模板与首页推荐 | 降低首次配置成本 |
| P1 | 文本对话式记录 | 直接降低手动记录成本 |
| P2 | 语音输入 | 在文本流程稳定后扩展输入方式 |
| P2 | 跨模块复杂自动化 | 依赖更成熟的数据模型与权限体系 |

## 指标与验证方式

当前没有线上数据，因此这里只定义未来可采集的验证指标，不填写虚构结果：

- 完成首次配置所需步骤与时间。
- 定制后高频模块的访问路径长度。
- AI 草稿的确认率、修改率与放弃率。
- AI 模块推荐被用户更改的比例。
- 撤销使用率与误写入反馈。
- 用户从表达意图到完成记录所需时间。

## 关键风险

- 过度定制可能提高学习成本。
- 身份模板可能形成刻板分类。
- AI 误判模块或字段会损害信任。
- 语音内容可能涉及更高的隐私风险。
- LocalStorage 难以支撑长期、多设备和高可靠的数据管理。

后续是否引入账号、云端数据库与同步能力，应在明确数据安全方案和真实使用需求后再决定，不能从当前原型直接推定。
