# Personal OS｜产品需求文档（PRD）

## 1. 产品概述

Personal OS 是一个本地优先的个人信息与行动管理 Web App。它尝试把用户在不同身份下分散的目标、学习、项目、记录与健康信息，组织进同一个个人系统。

当前项目以单文件 Web App 形式运行，数据保存在浏览器 LocalStorage 中，适合作为个人使用与产品概念验证。它不是已上线的多用户 SaaS，也未接入云端数据库或真实大模型。

## 2. 产品目标

- 用统一入口承载多身份、多场景的个人信息。
- 通过模块化结构减少工具切换和信息散落。
- 让 Dashboard 汇总近期重点，帮助用户从“记录”回到“行动”。
- 在本地优先的前提下，验证 Personal OS 的结构与使用方式。

## 3. 目标用户

现阶段主要面向同时承担多种身份、并有较强自我管理需求的个人用户，例如兼顾学习、项目、家教、创作与健康管理的人。

这是基于项目使用场景形成的目标用户假设，并非经大规模用户研究验证的结论。

## 4. 核心使用场景

1. 用户从 Dashboard 查看近期重点与各模块概况。
2. 用户进入对应模块，新增、查看或更新信息。
3. 数据保存在当前浏览器本地，刷新页面后仍可继续使用。
4. 用户在不同身份和任务之间切换时，仍通过同一套系统管理上下文。

## 5. 当前功能范围

| 模块 | 当前定位 |
|---|---|
| Dashboard | 汇总系统入口与重点信息 |
| PM Workspace | 管理产品与项目工作内容 |
| Learning | 记录学习内容与进展 |
| Journal | 承载日常记录与反思 |
| Tutoring | 管理家教相关信息 |
| Creation | 管理创作任务与产出 |
| Experience | 记录经历与体验 |
| Health | 记录健康相关信息 |

具体字段与交互以当前代码实现为准。本文不将未验证或未稳定的细节描述为完整产品能力。

## 6. 当前技术与数据边界

- 形态：单文件 Web App。
- 存储：浏览器 LocalStorage。
- 数据范围：当前设备、当前浏览器环境。
- 账号体系：当前不包含。
- 云同步与跨设备协作：当前不包含。
- AI：当前仅为模拟或概念探索，不具备真实模型理解与自动执行能力。

## 7. 非功能要求

- 本地可用：无需依赖完整后端即可运行核心流程。
- 状态清晰：新增、编辑和保存结果应有明确反馈。
- 数据可控：涉及未来 AI 写入时，必须由用户掌握最终决定权。
- 结构可扩展：模块之间保持相对独立，为后续个性化组合留出空间。

## 8. 成功标准

当前阶段不使用虚构的活跃、留存或转化数据。概念验证阶段主要观察：

- 用户能否理解各模块的职责。
- 用户能否完成“进入模块—记录—查看”的基本闭环。
- Dashboard 是否能承担统一入口。
- 模块结构是否适合后续扩展为个性化 Personal OS。

## 9. 后续规划摘要

后续版本重点探索模块 DIY、基于身份的首页定制，以及真实大模型驱动的聊天/语音记录入口。AI 生成的写入操作必须可预览、可确认、可撤销、可追溯，不能静默修改用户数据。
