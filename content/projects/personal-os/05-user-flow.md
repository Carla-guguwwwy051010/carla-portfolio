# Personal OS｜用户流程

## 当前核心流程

当前版本以手动浏览和手动记录为主，核心闭环如下：

```text
打开 Personal OS
→ 进入 Dashboard
→ 查看模块与重点信息
→ 选择目标模块
→ 新增或更新记录
→ 保存至 LocalStorage
→ 返回模块或 Dashboard 查看结果
```

## 场景一：记录模块信息

```text
Dashboard / 导航
→ 进入 Learning、Journal、Tutoring 等模块
→ 发起新增
→ 手动填写内容
→ 保存
→ 页面更新并展示记录
```

该流程反映当前原型的主要交互方式。数据保存在当前浏览器本地，不包含账号同步与跨设备流转。

## 场景二：跨身份切换

```text
查看 Dashboard
→ 判断当前任务所属场景
→ 切换到对应模块
→ 处理或补充信息
→ 返回 Dashboard
```

当前通过固定模块完成身份切换；未来可通过身份视图和个性化首页降低选择成本。

## 未来流程一：身份定制与 DIY

```text
首次进入 / 打开设置
→ 选择一个或多个身份
→ 系统推荐模块与首页布局
→ 用户增删、排序或调整模块
→ 预览 Personal OS
→ 确认并应用
→ 后续可随时再次编辑
```

身份推荐只生成初始方案，最终配置权属于用户。

## 未来流程二：聊天或语音记录

```text
打开 AI 助手
→ 输入文字或语音
→ AI 识别意图与关键信息
→ 推荐目标模块
→ 生成结构化记录草稿
→ 用户预览并修改
→ 用户确认
→ 写入对应模块
→ 生成可追溯的操作记录
```

例如，用户说：“今天给学生上了两小时课，讲了函数，他还是有些薄弱，下周继续复习。”AI 可建议生成一条 Tutoring 草稿，但在用户确认前不应写入正式数据。

## 异常与安全流程

- **识别不确定：** AI 展示候选模块或追问用户，不自行猜测并保存。
- **字段缺失：** 允许保留草稿，或提示用户补充必要信息。
- **分类错误：** 用户可在确认前更换模块。
- **已确认但需修改：** 用户可撤销操作或编辑记录。
- **操作复核：** 用户可查看输入内容、AI 解析结果、确认时间和最终写入位置。

## 流程设计原则

1. Dashboard 负责降低入口寻找成本。
2. 模块负责保持信息结构清晰。
3. AI 负责降低输入成本，不替代用户决策。
4. 涉及数据变更时，透明性与可恢复性优先。
