# Personal OS｜模块设计

## 设计思路

Personal OS 采用“统一入口 + 场景模块”的结构。Dashboard 负责聚合和导航，各业务模块负责保存特定场景的信息。这样的拆分既避免信息混杂，也为未来按身份组合模块提供基础。

## 当前模块结构

```text
Personal OS
├─ Dashboard
├─ PM Workspace
├─ Learning
├─ Journal
├─ Tutoring
├─ Creation
├─ Experience
└─ Health
```

## 模块职责

| 模块 | 主要职责 | 对应身份/场景 |
|---|---|---|
| Dashboard | 展示入口与重点概览 | 全局 |
| PM Workspace | 组织产品与项目相关工作 | 产品经理、项目参与者 |
| Learning | 记录学习内容与进展 | 学生、持续学习者 |
| Journal | 保存日常记录与反思 | 个人生活 |
| Tutoring | 管理家教相关信息 | 家教、教师 |
| Creation | 管理创作过程与产出 | 创作者、副业经营者 |
| Experience | 沉淀经历与体验 | 个人成长 |
| Health | 记录健康相关信息 | 健康管理 |

表中描述用于概括模块定位，不扩展为当前代码中未确认存在的字段或自动化能力。

## 模块之间的关系

- Dashboard 不替代业务模块，而是提供跨模块视图。
- 每条记录应有明确的主要归属，避免重复保存。
- 模块保持相对独立，以便未来按需启用或关闭。
- 跨模块关联属于后续可探索方向，当前不描述为已实现能力。

## 当前设计局限

当前模块由系统预设，适合验证整体结构，但并不代表每位用户都需要全部模块。固定首页也难以体现不同身份下的优先级变化。

## 未来模块化方案

### 1. 自由 DIY

用户可选择、隐藏、排序模块，并调整 Dashboard 卡片组合。系统提供基础骨架，用户决定最终结构。

### 2. 身份模板

用户可选择一个或多个身份，系统据此推荐模块与首页，例如：

- 学生：Dashboard + Learning + Journal + Health。
- 产品经理：Dashboard + PM Workspace + Learning + Experience。
- 家教：Dashboard + Tutoring + Journal + Learning。
- 创作者：Dashboard + Creation + Experience + Health。

这些组合是产品方案示例，不代表已上线模板。

### 3. 多身份组合

身份不是互斥标签。用户可以同时选择“学生 + 实习生 + 家教”，并继续调整系统推荐结果。身份用于生成初始结构，而不是限制用户。

### 4. AI 作为跨模块输入层

AI 不新增一个孤立的信息仓库，而是把自然语言转换为既有模块中的结构化草稿。所有建议写入都需由用户确认，并保留操作记录与撤销能力。
